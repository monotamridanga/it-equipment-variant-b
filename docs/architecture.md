# 2. Архитектура

## V-модель жизненного цикла

Требования и планирование → документация → архитектура → детализация → реализация → модульное тестирование → интеграционное тестирование → системная приёмка → сопровождение. Проверки сопоставлены разработанным артефактам.

## Состав решения

```
Пользователь CLI
    |
argparse: разбор параметров и команда
    |
EquipmentRepository: валидация и бизнес-правила
    |
sqlite3: таблицы equipment и events
```

## Модель данных

`equipment`: id, inventory_tag (UNIQUE), kind, model, serial (UNIQUE), location, status, assigned_to, created_at, updated_at.

`events`: id, equipment_id (FK), action, details, created_at.

Целостность обеспечивается ограничениями SQLite и явной проверкой переходов состояний.
